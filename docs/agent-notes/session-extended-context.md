# Session extended context — 2026-10-13

> Historical design: the session switch and ON-only maximum preference are superseded by [persistent model tiers and a read-only indicator](model-context-tiers.md). The catalog observations below remain dated capacity evidence, not current UI or runtime behavior.

## Product decision and evidence

The arbitrary per-model context slider/input and profile override feature are retired. A Composer expand icon immediately before the Fast Mode lightning button selects only the current conversation's standard or expanded context budget. Switching does not change other conversations or profile settings. Like Fast Mode, the toggle is process-local; plugin restart returns it to the default.

Codex Desktop's GPT-6.1 Sol tooltip showed **475K usable**, not the raw catalog window. A read-only projection of the local Codex model-cache capacity fields established:

| Model | Default raw window | Maximum raw window | Effective percent |
|---|---:|---:|---:|
| GPT-6.1 Sol | 500,000 | 872,000 | 95 |
| GPT-6 Astra / Sol / Luna, GPT-5.6 Sol / Terra / Luna, Reserve | 272,000 | 872,000 | 95 |
| GPT-5.5 | 272,000 | 272,000 | 95 |

This is a dated backend-catalog observation, **not a universal account entitlement**. The public bundled [Codex catalog](https://github.com/openai/codex/blob/main/codex-rs/models-manager/models.json) still advertised 272K for 6.1 Sol at investigation time. Codex can use [remote/catalog-cache metadata](https://github.com/openai/codex/blob/main/codex-rs/models-manager/src/manager.rs). No credentials were read or live model calls made to collect this projection; do not ship or read a user's Codex cache from the plugin at runtime.

[Codex's model metadata](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/openai_models.rs) distinguishes raw window, usable window (normally 95%), and automatic-compaction threshold (normally 90%). Thus 500K raw gives 475K usable; 872K raw gives 828.4K usable. These are different measurements, not extra tiers. `model_context_window` is [clamped to the model maximum](https://github.com/openai/codex/blob/main/codex-rs/models-manager/src/model_info.rs).

The final user decision supersedes the intermediate 500K-default proposal: the conversation icon OFF budget stays **272K**; ON is **500K** by default. Each model row gets a default-unchecked maximum-window preference. Checking it changes only that model's ON budget to its official maximum (872K for expandable models); OFF remains 272K. All ON budgets are bounded by the model maximum. Unknown or non-expandable models do not get an invented expansion.

## Ownership and compatibility

- DSH still owns prompt admission, token accounting, compaction triggers and durable conversation history. Advertising a larger client budget is not a server-capacity verification.
- `agent/request` forwards its exact turn signal to `prepareCall`. The registry binds the conversation choice and model to that signal, so the prepared metadata and provider stream use one budget generation. A later toggle affects the next request, not an already-prepared call.
- Separate ordinary and maximum adapter profiles avoid changing shared global model metadata.
- Stored `contextWindowOverrides` is an inert compatibility input. No arbitrary-budget setting row or slider exists; the new per-model checkbox changes only the expansion ON budget. Old arbitrary budgets cannot change live budgets or block unrelated saves.
- Settings remain manually staged. Save/Discard is in normal document flow above the fields, not a bottom overlay. Dirty state reflects actual differences, module changes retain the draft, and the owned Models dialog confirms before dropping edits.
